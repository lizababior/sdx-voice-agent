# VacMan — Frontend Implementation Plan

Owner: Jake · Nov 8, 2026

This plan turns [DESIGN.md](../DESIGN.md) into a build sequence. DESIGN.md decides how it looks and behaves. This file decides what to build, in which order, in which file. If the two disagree, DESIGN.md wins, except for the contract gaps in section 2, which need a team decision.

Related: [VacMan-3-Person-Build-Plan.md](VacMan-3-Person-Build-Plan.md) for the shared API contract and the schedule.

## 1. Stack and constraints

| Item | Choice |
| --- | --- |
| Framework | Next.js 16.4.5, App Router, Turbopack |
| React | 19.3 |
| Styling | Tailwind v4 (already set up in `globals.css` with the `@tailwindcss/turbopack` loader) |
| Voice | `@elevenlabs/react` v1: `ConversationProvider`, `useConversation` |
| Hosting | Vercel. The phone opens the Vercel HTTPS URL, so the mic works |
| Backend | Deandre's FastAPI behind ngrok, reached through Next `rewrites` |
| Target | 390 px wide phone, dark only, no desktop layout |

### Next.js 16 rules that affect this build

`next.config.ts` has `cacheComponents: true` and `partialPrefetching: true`. The docs are in `node_modules/next/dist/docs/01-app/`.

1. **Async `params`.** Do not `await params` at the top of `jobs/[id]/page.tsx`. Pass the `params` promise into a child component inside `<Suspense>` and await it there.
2. **Suspense for route hooks.** Wrap any component that calls `useParams`, `usePathname` or `useSearchParams` in `<Suspense>`.
3. **No `dynamicParams` export.** Call `notFound()` when the job ID is unknown.
4. **No `generateStaticParams`.** Jobs load at runtime. If you add it, it must return at least one param.
5. **Types.** `PageProps<'/jobs/[id]'>` and `LayoutProps` are generated by `next typegen`. `npm run build` generates them. Run it once if the editor shows "Cannot find name".

Almost all of the work is client components, so these rules touch only two files: `jobs/[id]/page.tsx` and the root `layout.tsx`.

## 2. Contract gaps to settle with Deandre (do this first)

DESIGN.md needs data that the API table in the build plan does not give us. Post these in the group chat at 2:05 so Deandre can build them in from the start.

| Gap | Why the design needs it | Proposal |
| --- | --- | --- |
| **No `substitute` event type.** The contract allows `part \| tool \| labor \| damage \| note`. | §4.2 shows a Substitute card with 3 options. | `find_substitute` also writes an event `{type: "substitute", item: "<original part>", options: [{part_no, name, price, why}]}`. |
| **No `invoice` event type.** | §4.3 opens the sheet when "the `generate_invoice` event arrives". | `generate_invoice` writes an event `{type: "invoice", total, invoice_url, line_items: [{label, amount}]}`. |
| **`generate_invoice` returns only `{total, invoice_url}`.** | The sheet lists line items (trip fee, labor, parts, tax). | Include `line_items` in the invoice event. The fallback is to show only the total and "View full". |
| **Events need a stable `id` and a `created_at`.** | The timeline must not duplicate cards, and cards show a time. | Each event has `id` (integer, increasing) and `created_at` (ISO string). |
| **Removed events.** `undo_last` returns `{removed}`. | §4.2 shows "Removed: 40/5 µF capacitor". | The events response keeps a removed event with `removed: true`, or the response has a `removed_ids` list. We pick the first option: it is simpler to diff. |
| **No "send" endpoint.** | §4.3 had a "Send to customer" button. | Decided: no sending. The button is now **Download invoice**. It saves the final invoice file from `/invoices/{job_id}`, and the contractor emails or shares it themselves. No new endpoint. Deandre only needs to keep serving `/invoices/{job_id}` as a complete, self-contained HTML page (styles inline). |

If Deandre cannot add something, the fallback column in section 9 says what we do.

## 4. Build order

Each step ends with something you can see in the browser and a check. The durations are estimates. The hard dates are the 3:15 merge, the 3:50 Loom and the 4:10 submit.

### Step 1 — Foundation (about 10 min)

1. **`globals.css`.** Replace the light and dark `:root` variables and the Arial rule.
   - Add `@theme` tokens from DESIGN.md §3: `--color-bg`, `--color-surface`, `--color-surface-2`, `--color-line`, `--color-text`, `--color-text-dim`, `--color-accent`, `--color-accent-ink`, `--color-ok`, `--color-danger`.
   - Add the event type colors as tokens: `--color-part` `#4DA3FF`, `--color-tool` `#A78BFA`, `--color-labor` `#34C759`, `--color-damage` `#FF453A`, `--color-note` `#A1A5AD`. Substitute uses `--color-accent`.
   - Set `body` to `bg-bg text-text`, font size 18 px (use `1.125rem` so text follows the system size), font stack `-apple-system, Roboto, "Segoe UI", sans-serif`.
   - Add a `.pb-safe` utility using `env(safe-area-inset-bottom)`, and `tabular-nums` for money.
   - Add a `prefers-reduced-motion` block that stops the pulse and bar animations.
2. **`layout.tsx`.**
   - Remove the `Geist` and `Geist_Mono` imports, because DESIGN.md uses the system font.
   - Export `viewport` with `width: "device-width"`, `initialScale: 1`, `viewportFit: "cover"`, `themeColor: "#0B0C0E"`.
   - Set the metadata title to "VacMan".
   - Keep `LayoutProps<"/">`.
3. **Check:** `npm run dev`, open the page on a 390 px viewport, confirm the dark background and the system font.

### Step 2 — Types and mock data (about 10 min)

1. **`lib/types.ts`.**
   ```ts
   type JobStatus = "not_started" | "in_progress" | "done";
   type Job = { id; customer; address; time; status; equipment; complaint; group: "today" | "upcoming" | "past" };
   type EventType = "part" | "tool" | "labor" | "damage" | "note" | "substitute" | "invoice";
   type JobEvent = { id: number; type: EventType; item: string; qty?: number; labor_min?: number;
     notes?: string; created_at: string; removed?: boolean;
     options?: SubstituteOption[]; total?: number; invoice_url?: string; line_items?: InvoiceLine[] };
   ```
   Match the field names in the shared contract. Add the optional fields from section 2.
2. **`lib/mock.ts`.** Six jobs (3 today, 2 past, 1 upcoming) with the customer, address, equipment and complaint fields. Add `MOCK_FEED`, a list of events in demo order: 2 parts, a labor entry, a damage note, a substitute, a removal, and an invoice with 4 line items.
3. **`lib/format.ts`.** `formatTime` ("2:41p"), `formatMoney`, `formatMinutes` ("30m", "1.5h").
4. **Mock switch.** `NEXT_PUBLIC_USE_MOCK=1` in `.env.local` makes `api.ts` and `useEvents.ts` return mock data. Unset it for the real backend. The switch removes the merge risk: the same components run on both.

### Step 3 — Job list, DESIGN.md §4.1 (about 25 min)

1. **`JobCard`.** Props: `customer, address, time, equipment, complaint, status, dim`.
   - The whole card is one `<Link>`, minimum height 96 px, radius 16, `bg-surface`, 1 px `line` border.
   - Layout: status dot and customer on line 1, address on line 2, `time · equipment` on line 3, complaint and `›` on line 4.
   - Dot: orange = in progress, green = done, gray = not started. An in-progress card has an orange border.
   - `active:bg-surface-2` for press feedback. No `hover:`.
   - Past cards use `text-dim`.
2. **`page.tsx`.**
   - Greeting "Hi, Mike" at 28 / 700, then a dim line with the date and job count.
   - Three sections: TODAY, UPCOMING, PAST. Section labels use the label style (13 / 600, uppercase, 0.06em tracking).
   - Order: today's in-progress job first, then today's others by time, then upcoming, then past.
   - No bottom nav, menu or search.
3. **Data.** Start as a server component that renders mock data. When the backend is live, fetch `/api/jobs?tech_id=t1` from a client component or with `fetch` inside `<Suspense>`. Because `cacheComponents` is on, uncached runtime data needs the Suspense boundary.
4. **Check:** 390 px screenshot against the wireframe. Every card is at least 96 px tall and no card text goes below 14 px.

### Step 4 — Deploy early (about 10 min)

Do this before the session screen so the Vercel and phone checks do not wait for the end.

1. Create the Vercel project and deploy.
2. Set the env vars in Project Settings: `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID` (Liz's account) and `BACKEND_URL` (Deandre's ngrok URL, when posted). Also set `NEXT_PUBLIC_USE_MOCK=1` until the backend works.
3. Add `rewrites` in `next.config.ts`:
   - `/api/jobs/:path*` → `${BACKEND_URL}/api/jobs/:path*`
   - `/invoices/:path*` → `${BACKEND_URL}/invoices/:path*`
   - Add the request header `ngrok-skip-browser-warning: 1`. If the rewrite config cannot set request headers, ask Deandre to return that header handling in FastAPI or use a Next route handler proxy for `/api/jobs/*`.
   - Skip the rewrite when `BACKEND_URL` is unset, so the build does not break.
4. **Check:** open the Vercel URL on a real phone. The job list loads. `/api/run-code` returns 404.

### Step 5 — Session shell, DESIGN.md §4.2 (about 20 min)

1. **`jobs/[id]/page.tsx`.** A server component with no `await` at the top:
   ```tsx
   export default function Page({ params }: PageProps<"/jobs/[id]">) {
     return <Suspense fallback={<SessionSkeleton />}><Session params={params} /></Suspense>;
   }
   async function Session({ params }: Pick<PageProps<"/jobs/[id]">, "params">) {
     const { id } = await params;
     return <JobSession jobId={id} />;
   }
   ```
   `JobSession` calls `notFound()` if the job does not exist.
2. **`JobSession` layout.** Full-height flex column: sticky header, scrolling timeline, fixed dock. Use `h-dvh` so the mobile browser bars do not push the dock off screen.
3. **`JobHeader`.** "‹ Jobs" back link (56 px target), customer at 28 / 700, then address and `equipment · complaint` in dim text. Sticky, `bg-bg`, bottom border.
4. **`Timeline`.** A scroll container. Empty state: the dim centered text "Nothing logged yet. Tap the mic and say what you did." No illustration.
5. **`MicDock`.** Fixed at the bottom, `bg-bg`, top border, `pb-safe`. Contains a 112 px mic button, the caption, and the secondary "Close out job" button (56 px tall, outlined). For now the mic shows the idle state only.
6. **Check:** the dock stays above the iPhone home bar, and the header does not move when the timeline scrolls.

### Step 6 — Timeline and cards, DESIGN.md §4.2 (about 25 min)

1. **`useEvents(jobId)`.**
   - Real mode: `GET /api/jobs/{id}/events` every 2 seconds with `setInterval`, cleared on unmount.
   - Keep events in state keyed by `id`. Merge new ones, so cards already on screen do not re-render or re-animate.
   - Return `{ events, isNew(id), error }`.
   - Mock mode: add one event from `MOCK_FEED` every 3 seconds.
   - On a fetch error, keep the old events and show the inline sentence "Lost connection. Retrying." No toast.
2. **`EventCard`.** Left border 4 px in the type color. Row 1: uppercase label (Part, Tool, Labor, Damage, Note) in the type color. Row 2: the item at 20 / 600. Right side: `×qty` or minutes. Bottom right: dim time. Never rely on color alone. The label word always shows.
   - Map type to color and label in one lookup object at the top of the file.
3. **Animation.** A new card slides up and fades in over 200 ms, and flashes `surface-2` once. Use a CSS keyframe class set only on cards that `isNew`. Under reduced motion, show the card with no motion.
4. **Auto-scroll.** After a new card renders, scroll the container to the bottom. If the tech has scrolled up to read, do not jump. Only auto-scroll when they are within about 80 px of the bottom.
5. **Removed events.** Fade the card out, then replace it with the dim line "Removed: {item}". No undo button.
6. **`SubstituteCard`.** Orange border, label "Substitute", title "Substitute for {original}". Up to 3 rows, each 56 px tall: part number and name, price on the right, one-line "why" under it in dim text.
7. **Check:** run the mock feed. Cards appear in order, auto-scroll works, and the removed line shows.

### Step 7 — Voice and mic states, DESIGN.md §4.2 (about 20 min)

Verified in `node_modules/@elevenlabs/react/dist/conversation/useConversation.d.ts`: the hook returns `status`, `mode` (`"speaking" | "listening"`), `isMuted`, `startSession`, `endSession`, `sendUserMessage`, `getInputVolume` and `getOutputVolume`. `dynamicVariables` is part of the session options. Confirm the exact option shape in `HookOptions` (`conversation/types.d.ts`) before you pass it.

1. **`VoiceAgent.tsx`.** Make it the provider only: wrap the session screen in `ConversationProvider`. Remove the `run_code` handler and the transcript list.
2. **Start flow.** On the first tap:
   1. `navigator.mediaDevices.getUserMedia({ audio: true })`. If it throws, set the mic state to blocked.
   2. `fetch("/api/conversation-token")` and read `token`.
   3. `startSession({ conversationToken, connectionType: "webrtc", dynamicVariables: { job_id, customer_name, equipment, complaint } })`.
   4. `navigator.vibrate?.(10)`.
3. **Mic state mapping.** Derive one `micState` value in `MicDock`:

   | Condition | State | Caption |
   | --- | --- | --- |
   | `status` is disconnected, no error | `idle` | "Tap to talk to VacMan" |
   | `status === "connecting"` | `connecting` | "Connecting…" |
   | `status === "connected"` and `mode === "listening"` | `listening` | "Listening…" |
   | `status === "connected"` and `mode === "speaking"` | `speaking` | "VacMan is talking" |
   | mic permission denied or `onError` | `error` | "Mic is blocked. Tap here to fix" (red) |

4. **Visuals.** 112 px orange circle with a mic icon. Connecting: spinning ring. Listening: slow pulsing ring. Speaking: three animated white bars. Error: gray circle. Use CSS animations. Make the pulse static under reduced motion. Do not add a library.
5. **Behaviour.** One tap starts, one tap ends. The caption is an `aria-live="polite"` region and the button has `aria-pressed`.
6. **"Close out job" button.** It calls `sendUserMessage("Close it out")`, which has the same effect as the tech saying it. It is disabled when the session is not connected.
7. **Wake Lock.** `useWakeLock(active)` requests `navigator.wakeLock.request("screen")` while `status === "connected"`, releases on end, and re-requests on `visibilitychange`. Wrap it in try/catch: it may be unsupported.
8. **Errors.** Show persistent inline sentences under the caption, for example "Lost connection. Tap the mic to reconnect."
9. **Check:** on a real phone over the Vercel URL, start a session with your own throwaway agent and watch all five states. Then swap to Liz's agent ID.

### Step 8 — Invoice sheet, DESIGN.md §4.3 (about 20 min)

1. **Trigger.** When `events` contains an `invoice` event that has not been shown yet, open the sheet. Store the shown ID in state so a poll does not reopen it after the tech closes it.
2. **`InvoiceSheet`.** A bottom sheet at about 85% height, 24 px top radius, `bg-surface`, dimmed backdrop.
   - Drag handle, "Invoice ready", the total at 48 / 700 with tabular numbers, then `customer · address` in dim text.
   - A bordered list of line items (label left, amount right).
   - Primary orange button "Download invoice". Outlined secondary buttons "Print" and "View full".
   - "Done" button. Closing also works from the handle and the backdrop.
3. **Print.** Open the invoice in the iframe and call `window.print()` on it, or open `invoice_url` in a new tab as a fallback.
4. **View full.** Loads `/invoices/{job_id}` in an iframe inside the sheet. The path goes through the rewrite.
5. **Download invoice.** A plain link to the invoice that the browser saves as a file:
   ```tsx
   <a href={`/invoices/${jobId}`} download={`Invoice-${customer}-${jobId}.html`}>Download invoice</a>
   ```
   - The path is same-origin because of the rewrite, so the `download` attribute works.
   - Style the link as the 56 px primary button. Use `active:` press feedback.
   - After the tap, show the persistent line "Saved. Email or share it from your Files." No toast, no dialog.
   - Fallback: if the phone opens the file in a tab instead of saving it (older iOS Safari), the same page already shows a Share option, so no extra work. For a PDF, the contractor uses Print and "Save as PDF".
   - The file must work offline in an email: the invoice HTML needs inline styles and no external assets. Ask Deandre to confirm this.
6. **Status.** While the tool runs, show "Building invoice…" as text in the dock caption.
7. **Check:** the mock feed ends with an invoice event, and the sheet opens once.

### Step 9 — Polish and phone test (the rest of the time)

Run through DESIGN.md §6 and §7:

- Every control is at least 56 px and gives press feedback within 100 ms using `active:` styles.
- No hover styles, no modals, no auto-dismissing toasts, no confirm dialogs.
- Text uses `rem`. Body contrast is at least 7:1. The tokens already meet it.
- Check loading and empty states for the job list, the timeline and the sheet.
- Test in direct sunlight on a real phone, with the brightness up.
- Check iPhone Safari and Android Chrome if both are available.

## 8. Risks

| Risk | Mitigation |
| --- | --- |
| Backend is late | The mock switch lets all UI work finish without it. |
| ngrok warning page breaks fetches | Send `ngrok-skip-browser-warning: 1`. Fall back to a route handler proxy. |
| ngrok URL changes | Keep `BACKEND_URL` in Vercel only. Redeploy after a change. |
| Mic blocked on iOS Safari | Needs HTTPS. The Vercel URL provides it. Show the blocked state with a clear instruction. |
| Polling causes duplicate cards | Key events by `id` and merge. Never replace the whole list. |
| Suspense or cache build errors on `/jobs/[id]` | Follow section 1. Do not await `params` at the top of the page. |
| `dynamicVariables` option shape is different from what this plan assumes | Read `HookOptions` in `conversation/types.d.ts` first. |

## 9. Fallbacks if the contract gaps are not met

| Missing | What the frontend does |
| --- | --- |
| No `substitute` event | Parse the `find_substitute` result from the tool call: use `onMessage` or the tool response, and add the card locally. If neither is available, show the substitute as a `note` card with the text. |
| No `invoice` event | After `generate_invoice`, the agent reads the total aloud. Add a "View invoice" button to the dock that opens the sheet with `/invoices/{job_id}` in the iframe. The total stays blank. |
| No `line_items` | The sheet shows only the total and "View full". |
| No `created_at` | Use the time the browser first received the event. |
| No removal flag | Diff the previous list against the new one. A missing ID becomes a "Removed" line. |

## 10. Out of scope

Same as DESIGN.md §9: light theme, desktop layout, login, settings, search, offline mode, and any animation beyond those listed. Also out of scope: sending the invoice from the app (email or SMS), and photo upload.
