# VacMan — Frontend Implementation Plan

Owner: Jake · Nov 8, 2026

This plan follows [VacMan-Build-Plan-v2.md](VacMan-Build-Plan-v2.md), which is the main build doc, and [DESIGN.md](../DESIGN.md) for the look. If this file disagrees with v2, v2 is correct. If it disagrees with DESIGN.md, DESIGN.md is correct.

## 1. Architecture

- One Next.js app (this repo) on **localhost**. No separate backend, no ngrok, no Vercel. The mic works on localhost without HTTPS.
- The agent tools are **client tools**. The phone page runs them in the browser. Handlers call `/api/sandbox/*` (Deandre). Those routes call Daytona with the server-side key. The browser never has an API key.
- The phone page sends console events over `BroadcastChannel("vacman")`. `/console` listens. Both pages must be open in the same browser.
- One work order: `data/work-order.json` (the Johnson job). The home page shows it as the only job card.

Next.js 16 rules that apply (docs in `node_modules/next/dist/docs/01-app/`):

1. `cacheComponents` is on. Do not read the current time or random values while prerendering a client component. Read them after mount, or use `useSyncExternalStore` with an empty server snapshot.
2. Route `params` are async, and route hooks need `<Suspense>`. There are no dynamic routes now, so these rules do not apply yet.
3. `PageProps` and `LayoutProps` are generated by `next typegen`. `npm run build` generates them.

## 3. Tool contract

From v2 section 5. The handlers are in `VoiceAgent.tsx`.

| Tool | Handler |
| --- | --- |
| `log_job_note` | `add`: validates, refuses a second `DIAG-STD`, adds a note, returns `{saved: true, note_id}`. `remove`: marks the note removed, returns `{removed: true}`. Returns only these fields. |
| `run_python` | `POST /api/sandbox/run` with `{sandboxId, code}`. Returns stdout, or the error text. Adds a result chip. |
| `create_invoice` | `POST /api/sandbox/invoice` with `{sandboxId, workOrder, notes}`. Opens the invoice sheet. Returns the invoice number and total, and any unpriced notes. |

Handlers return strings (JSON text for the objects), because the hook's `ClientToolResult` is `string | number | void`.

Every call sends `tool_start` and `tool_end` to the console. Latency is the time from the final user transcript to the start of the agent's speech.

## 5. Test plan

Needs `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID` (run `npm run agent:setup` after every pull) and `DAYTONA_API_KEY` in `.env.local`.

1. `npm run dev`. Open `/` and `/console` in two tabs of the same browser. Tap the job card to open `/job`.
2. The sandbox status goes from "warming" to "warm". The mic is disabled until then.
3. Run the demo script from v2 section 3, line by line. Check:
   - Notes appear with the right category, and the quantity shows.
   - Saying "scratch that" shows "Removed: …".
   - A calculation shows a "Calc" chip with the superheat.
   - "Wrap up the job" ends with the invoice sheet, $707.92, "Sent to office for review".
4. Download saves a `.pdf` that opens. Print opens the print dialog.
5. The console shows the transcript with language, each tool call with timing, the Python code with its output, and a latency badge on each agent turn.
6. Close the console and open it again in the middle of a run. It shows the history.
7. A phone-width window (390 px): no horizontal scroll, the dock stays above the bottom edge, taps are at least 56 px.

## 6. Known gaps and risks

| Risk | Note |
| --- | --- |
| Language in the console is a guess | The ElevenLabs message has no language field. `lang.ts` uses accents and common Spanish words. |
| Latency is approximate | The user transcript arrives a little after the speech ends, so the measured time is slightly short. |
| A real phone cannot reach `localhost` | Test the layout in a 390 px window. Use a tunnel only for a one-time phone check. |
| iOS Safari shows only the first page of a PDF in an iframe | The invoice is one page. Download works. |
| The page reload clears the notes | State lives in the page. The demo is one run. |
| Sandbox start can hang | Deandre's route retries once. The header shows "failed" with a retry. |
| `run_python` result chip shows the last line of stdout | If the agent prints more than the result, the chip can show the wrong line. |
